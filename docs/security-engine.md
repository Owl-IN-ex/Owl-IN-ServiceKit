# Security Engine

Security-модуль **Owl-IN ServiceKit** использует корреляцию нескольких признаков, а не одну проверку.

## Что учитывается

В зависимости от доступных данных анализируются:

- текущая нагрузка CPU/GPU;
- расположение исполняемого файла;
- цифровая подпись и издатель;
- Run / RunOnce;
- Scheduled Tasks;
- Services;
- WMI persistence;
- Defender exclusions;
- сетевые соединения;
- попытка маскировки под системный процесс;
- parent/child process chain.

## Важный принцип

`unsigned + AppData` не равно «вирус».

Один слабый признак не является достаточным основанием для автоматического обезвреживания. Решение опирается на совокупность данных и уровень уверенности.

## Изоляция

Текущий сценарий изоляции:

**Rescan → SHA-256 → Backup → Disable persistence → Stop → Quarantine → Verify**

Восстановление возвращает файл и сохранённые настройки, но не запускает программу автоматически.

## WMI

WMI persistence сейчас используется как диагностический признак. Автоматическое удаление WMI consumer/filter binding не выполняется.

## Defender

Microsoft Defender используется как дополнительный источник контекста. Его вердикт не является обязательным условием ни для обнаружения, ни для отсутствия проблемы.
