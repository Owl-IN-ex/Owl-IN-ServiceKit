# Обновления и релизы

Для **Owl-IN ServiceKit** используется простой portable-подход без отдельного auto-updater.

## Как оформляется релиз

Исходники и документация хранятся в репозитории. Готовый EXE в git не коммитится.

После завершения локального тестирования:

1. обновляется репозиторий;
2. создаётся tag вида `v1.0.3`;
3. создаётся GitHub Release `Owl-IN ServiceKit 1.0.3`;
4. в Release прикладывается **тот самый EXE, который уже прошёл локальное тестирование**;
5. для файла фиксируется SHA-256.

Пример имени asset:

```text
Owl-IN-ServiceKit-1.0.3.exe
```

## Текущая схема обновления

В версии 1.0.3 автоматического обновления и автоматической замены EXE нет.

Пользователь вручную скачивает нужный релиз и заменяет старый EXE.

Versioned runtime хранится отдельно в `%LOCALAPPDATA%\Owl-IN\ServiceKit\runtime\`, поэтому замена внешнего EXE не требует вручную переносить runtime-кэш.

## SHA-256

SHA-256 используется как цифровой отпечаток релизного файла. В GitHub Release должен попадать ровно тот бинарник, который был протестирован локально.
