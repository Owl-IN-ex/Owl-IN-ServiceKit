# Выпуск Owl-IN ServiceKit

## Рабочий цикл

1. Разработка и промежуточное тестирование выполняются на локальных Functional Test-сборках.
2. После стабилизации версии формируется отдельная релизная сборка с финальными метаданными версии.
3. Релизная сборка проходит итоговую проверку как готовый portable EXE.
4. Исходники, история изменений и документация приводятся в состояние выпускаемой версии.
5. Для зафиксированного состояния репозитория создаётся Git tag вида `v1.0.4`.
6. На основе этого тега создаётся GitHub Release `Owl-IN ServiceKit 1.0.4`.
7. К выпуску прикладывается **тот же EXE, который прошёл итоговую проверку**.
8. Для опубликованного файла фиксируется SHA-256 и сверяется с локально проверенным бинарником.

## Выпуск 1.0.4

Проверенный релизный файл:

```text
Owl-IN-ServiceKit-1.0.4.exe
SHA-256: f11c27be40cb61e4486b182826841f5c27b5a844c6a091163f51fcf5d722b8c6
Статус: готов к публикации
```

Для проверки контрольной суммы рядом с EXE можно публиковать файл:

```text
Owl-IN-ServiceKit-1.0.4.exe.sha256
```

## Важно

Официальный EXE не пересобирается после итогового тестирования без повторной проверки. В GitHub Release должен попадать тот же бинарник, который был проверен локально.

Готовые EXE не коммитятся в исходники. Они размещаются только в GitHub Releases.
