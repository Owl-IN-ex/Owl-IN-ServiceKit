# Owl-IN ServiceKit — история версий

## 1.3.0 — 2026-10-06

- Добавлен диспетчер процессов в Expert Mode.
- Отдельная сценарная сборка содержит 14 примеров, включая монитор с вымышленным завершением и TCP-трафиком.


- В Easy → «Найденные проблемы» добавлен подтверждаемый план пакетного исправления.
- Можно исключить отдельные действия перед запуском; неподходящие проблемы показываются отдельно.
- Правила включают подтверждённые отклонения DNS, мешающий WinINET proxy/PAC и отключённые службы Windows Update.
- Каждый шаг повторно проверяет условия и настройки, создаёт проверяемый backup, выполняет действие и проверяет результат; при неудаче выполняется откат.
- Пакеты сохраняются атомарно с SHA-256; повторный запуск и параллельные пакетные изменения запрещены.
- Доступны отдельные итоги, откат каждого применённого изменения и продолжение проверок после перезагрузки.
- Quick Scan дополнен проверкой Windows Update; неработающие службы больше не считаются подтверждённым успехом исправления.

- Рабочая документация отделена от исторических тестов; добавлен единый актуальный регрессионный чек-лист.
- Сборщик читает версию из проекта, создаёт SHA-256 и сохраняет предыдущий EXE при неудаче; WebView2 SDK зафиксирован на фактически используемой версии 1.0.3912.50.

- При отсутствии найденных проблем пустой план исправления скрывается; результаты выполненных действий и отдельный откат остаются доступны.

- Easy Mode показывает только ошибки и предупреждения; справочные состояния не меняют зелёный итог и остаются в исходной диагностике Expert Mode. Неопределённые результаты не заменяются нормой.

- Блок «Что не работает?» запускает конкретные Easy-проверки интернета, производительности и Windows Update вместо дублирования меню.

- Добавлена декларативная база из шести правил текущей диагностики и шести групп интерпретации событий. Совпадение проверяется по условиям, журналу, точному провайдеру, ID, времени и выбранному симптому.
- Easy получил объяснения, доказательства и отдельную историю связанных сбоев; пустой дополнительный анализ не занимает место.
- Более поздний успех установки того же обновления снимает прежнюю неудачную запись; разные обновления не смешиваются. Старые записи не повышают текущий статус.
- Expert использует общую базу интерпретаций, читает Critical вместе с Error/Warning и показывает недоступные журналы и ограничения выборки.

## 1.2.1 — 2026-10-05

- Нажатие на крестик скрывает главное окно в область уведомлений вместо завершения программы.
- Значок в трее открывает окно одиночным или двойным нажатием; контекстное меню содержит команды «Открыть» и «Выйти».
- Контекстное меню значка оформлено как компактная панель Owl-IN: скруглённое окно, тёмная подложка, тонкая рамка и скруглённая подсветка действий вместо стандартного меню Windows.
- При первом закрытии в трей Windows показывает короткое уведомление о продолжении работы программы.
- Повторный запуск активирует уже работающий экземпляр и не создаёт второе окно.
- JSON-backup DNS, WinINET, служб Windows Update, PendingFileRenameOperations и карантина записываются через временный файл с атомарной заменой.
- После записи проверяются существование, ненулевой размер, чтение, схема JSON и SHA-256 файла; WinHTTP-backup проходит аналогичную проверку как текстовый файл.
- Repair Engine не начинает изменение, если фактический файл backup отсутствует, пуст, не читается или не проходит проверку.
- Имена backup получили миллисекунды и случайный суффикс, чтобы параллельные или быстрые действия не перезаписывали точки отката.

## 1.2.0 — 2026-09-25

- Easy-сценарии дополнены фактическими действиями: перезапуск сетевого и Wi-Fi адаптера, восстановление служб Windows Update, Plug and Play-сканирование аудио/Bluetooth/обычных устройств, очистка старых файлов пользовательского TEMP и явное завершение конкретного тяжёлого процесса.
- Для служб Windows Update создаётся проверяемый backup исходных StartMode/состояний; при неудаче они восстанавливаются.
- Очистка диска ограничена TEMP текущего пользователя и файлами старше 14 дней; занятые файлы пропускаются, а необратимость явно указана до подтверждения.
- Добавлен Reboot/Resume: атомарный файл состояния с SHA-256, задача в Task Scheduler, продолжение целевой проверки после входа и удаление задачи после завершения.
- Windows Memory Diagnostic теперь можно запустить как продолжаемую операцию: после входа ServiceKit читает событие `MemoryDiagnostics-Results` и сохраняет итог в истории Repair Engine.
- Проверка `hosts` теперь отличает ошибку чтения от пустого файла, корректно читает большие UTF-8 списки и отдельно считает блокировки, перенаправления и строки с некорректными IP. Устранён конфликт с системной PowerShell-переменной `$Host`, из-за которого анализ останавливался на первой активной записи. Автоматическое изменение `hosts` не выполняется.
- В RAM/BSOD числовой `CrashDumpEnabled` заменён понятным названием режима записи дампа; отдельно поясняется, что пути CrashControl являются настройками назначения и не подтверждают наличие дампа.
- Recovery Center теперь раскрывает содержимое `PendingFileRenameOperations`: для каждой записи показывает удаление либо исходный и конечный путь переименования/замены. Очередь остаётся read-only.
- Служебные префиксы `*1`/`*2` и `\??\` скрываются в отображаемых путях отложенных операций, но сохраняются без изменений в RAW.
- В Expert Recovery добавлена контролируемая очистка `PendingFileRenameOperations`: перед изменением создаётся backup, после изменения проверяется реестр, доступен отдельный откат. Файлы по указанным путям не удаляются принудительно.
- Абсолютные локальные и сетевые пути во всех разделах, включая технические данные и RAW, автоматически становятся ссылками: папка открывается, а файл выделяется в Проводнике.
- Recovery Center больше не показывает сохранённый backup как «доступный откат», если текущее состояние уже совпадает с ним и применять откат не требуется.
- Expert Recovery показывает все активные backup DNS, WinINET, WinHTTP и PendingFileRenameOperations и позволяет явно выбрать, какое состояние восстановить. Backend проверяет имя и тип выбранного backup.
- В блоке Expert Recovery «Откат изменений» добавлен переключаемый режим удаления: корзина включает выборочное удаление точек отката, повторное нажатие возвращает обычное восстановление. Каждый файл удаляется только после отдельного подтверждения и проверки имени backend.
- Системные окна подтверждения браузерного вида заменены собственным диалогом Owl-IN ServiceKit. Удаление и необратимые действия выделяются красным акцентом; адрес `app.owl-in.local` пользователю больше не показывается.

- Easy Mode получил единые проверяемые итоги действий: «Исправлено», «Не помогло — изменение отменено» и «Автоматически исправить небезопасно».
- Обратные сервисные действия «Остановить WLAN» и «Остановить службы обновления» убраны из пользовательских сценариев.
- Действия запуска Bluetooth, печати и повторного поиска устройств показываются только при обнаруженном отклонении.
- Исправлено обнаружение оставшегося WinINET proxy/PAC в сценарии «После VPN пропал интернет».
- При ошибке DNS после VPN доступны очистка кеша и контролируемый возврат DNS к DHCP с повторной проверкой.
- Если безопасного автоматического действия нет, Easy Mode прямо сообщает об этом и показывает конкретный следующий шаг.
- После успешного отката DNS, WinINET или WinHTTP использованный backup сохраняется для истории, но больше не показывает повторную кнопку восстановления.
- Старые WinINET-backup тоже не создают кнопку отката, если текущие ProxyEnable, ProxyServer и AutoConfigURL уже совпадают с сохранённым состоянием.
- История версий в приложении снова разделяет фактический релиз 1.1.0 и релиз 1.2.0.
- Из верхней панели удалены дублирующие индикаторы прав администратора и ID сессии; там оставлены только переключатель режима и язык.
- Действия в Expert Mode сгруппированы по назначению: откат, перезагрузка, системные инструменты и остальные операции; повторяющиеся пояснения возле кнопок удалены.

## 1.1.0 — 2026-09-22

- Проверка интернета теперь учитывает пользовательский WinINET proxy/PAC и подтверждает фактическое открытие сайта, а не только прямой TCP-доступ к порту 443.
- Недоступный proxy, оставшийся после VPN, больше не считается исправным подключением и показывается как причина проблемы в сетевых Easy-сценариях.
- Добавлено действие отключения пользовательского proxy с повторной проверкой открытия сайта.
- Исправлена несовместимость этапов сетевого исправления с Windows PowerShell 5.1, вызывавшая ошибку `Типы аргумента не совпадают`.
- Easy-раздел «Восстановление» переведён на действия: обычная перезагрузка, дополнительные параметры запуска, восстановление системы, параметры восстановления Windows и отмена перезагрузки доступны сразу.
- После запуска перезагрузки отображается состояние **«Запланирована»**; оно очищается после отмены, следующей загрузки Windows или устаревания записи.
- Диагностика Recovery перенесена ниже действий и свёрнута по умолчанию; справочные блоки, не помогающие выполнить действие, удалены.
- Обозначение Functional Test удалено из интерфейса, метаданных EXE, логов и пользовательских сведений о версии; тестовый номер используется только в названии внешней папки и архива.

## 1.0.4 — 2026-09-20

- Возвращена финальная компоновка меню из релиза 1.0.3: при небольшой высоте окна пункты становятся компактнее, список прокручивается, а нижняя кнопка меню остаётся доступной.
- Восстановлено корректное разворачивание фирменного окна: оно учитывает рабочую область монитора и больше не уходит под панель задач Windows. Минимальный размер 1180 × 760 также принудительно соблюдается с учётом масштаба экрана.
- В верхнюю часть «О программе» вынесены переход на сайт Owl-IN и ручная проверка обновлений.
- Проверка обновлений ускорена: WebView2 и системная часть запускают независимые запросы параллельно и используют первый успешный ответ.
- Системная проверка одновременно запрашивает перенаправление `github.com/releases/latest` и GitHub API; общий предел ожидания — около 4 секунд.
- Если оба источника GitHub недоступны, используется короткий файл версии на официальном сайте как резервный источник.
- Технические ошибки .NET больше не показываются пользователю напрямую.
- Время выполнения проверки обновлений больше не выводится в интерфейсе; оно остаётся только в техническом журнале.
- История Quick Scan сохраняется и читается непосредственно оболочкой EXE, без зависимости от локального сервера разработки.
- Добавлена ротация `host-latest.log` и очистка старых временных файлов операций.
- Модуль запуска очищает старые каталоги среды выполнения, сохраняя текущую и одну предыдущую версию.
- Версия продукта, EXE, модуля запуска и каталога среды выполнения синхронизированы для релиза 1.0.4.
- Кнопка сайта в разделе «О программе» переименована в «Официальный сайт».

## 1.0.3 — 2026-09-19

- Унифицировано официальное имя продукта: во всех пользовательских текстах используется **Owl-IN ServiceKit**.
- `ServiceKit` отдельно больше не используется как самостоятельное пользовательское имя; оно остаётся только частью технических идентификаторов там, где переименование не требуется.
- Финальный portable-файл теперь формируется с версией в имени: `Owl-IN-ServiceKit-1.0.3.exe`.
- Синхронизированы Product Name, версия, launcher, runtime-каталог и сообщения сборщика.

## 1.0.2 — 2026-09-19

- Исправлены визуальные артефакты, обрезание секций и градиентных световых зон при быстром переключении разделов.
- Удалены `content-visibility:auto` и paint containment для рабочей области: они оказались нестабильными при частой замене DOM в WebView2.
- Навигация теперь коалесцирует быстрые клики и отрисовывает только последний выбранный раздел.
- При переходе между страницами позиция прокрутки гарантированно сбрасывается до начала нового раздела.
- Автоматический запуск тяжёлой Expert-диагностики отложен на 220 мс и отменяется, если пользователь уже ушёл с раздела.
- Старт диагностики больше не вызывает дополнительную полную перерисовку Expert-страницы.
- Фоновые световые зоны рабочей области вынесены в стабильный слой, независимый от содержимого текущей страницы.

## 1.0.1 — 2026-09-19

- Ускорены переходы между разделами и снижена нагрузка WebView2 на больших Expert-экранах.
- PowerShell-диагностика вынесена из UI-потока и сериализована: тяжёлые проверки не запускаются параллельно при быстром переключении разделов.
- RAW JSON теперь формируется только по запросу пользователя.
- Боковая навигация больше не пересоздаётся целиком при каждом переходе.
- Доработана portable-упаковка в один распространяемый EXE с внутренним runtime-кэшем.
- Синхронизированы Product/File/Assembly/Informational Version, launcher и runtime-каталог.

## 1.0.0 — 2026-09-19

Первый стабильный релиз Owl-IN ServiceKit.

- Easy Mode: Quick Scan, сценарии «У меня проблема», найденные проблемы, восстановление и понятные человеку результаты.
- Expert Mode: конфигурация, сеть, накопители, RAM/BSOD, Windows Update, службы и автозапуск, события, безопасность, RAW-данные.
- Расширенная диагностика сети и компонентов, влияющих на неё.
- Диагностика подозрительной фоновой активности, persistence и безопасная изоляция кандидатов.
- Кастомное окно Owl-IN, адаптивная компоновка, полноширинный Expert.
- Self-contained Windows-сборка и portable launcher.
- После отключения VPN Easy-сценарий теперь обнаруживает оставшийся пользовательский WinINET proxy/PAC (включая локальные proxy вида `127.0.0.1`) и предлагает контролируемое отключение с backup, verify и rollback. Ранее сбрасывался только WinHTTP proxy.
