# План разработки

Это **рабочий список задач**, а не обещание релизов и не описание того, каким Owl-IN ServiceKit обязан стать. Порядок, состав и номера версий могут меняться по ходу разработки.

## 1.0.4 — Аудит и техническая уборка

Техническая уборка стабильной базы.

- привести историю быстрых проверок к нормальной работе внутри EXE;
- проверить старые служебные ветки и заглушки;
- провести аудит связи интерфейса с системной частью;
- сделать единый источник версии и метаданных сборки;
- добавить в приложение ссылку на официальный сайт Owl-IN ServiceKit;
- очищать старые кэши среды выполнения;
- добавить ротацию логов;
- дополнительно проверить Windows 10/11, DPI, запуск с правами администратора и без них.

## 1.1.0 — Диспетчер процессов и единый механизм восстановления

### Expert → Процессы

Текущий план задач:

- живой список процессов;
- PID / PPID;
- CPU / GPU / RAM;
- путь к EXE;
- цифровая подпись и издатель;
- SHA-256;
- дерево процессов;
- сетевые соединения;
- поиск процесса, удерживающего файл;
- завершение процесса;
- завершение дерева;
- защита критических системных процессов;
- переход к связанным Run/RunOnce, службам и заданиям планировщика;
- действие **«Обезвредить»** для подозрительного процесса.

Черновая схема действия «Обезвредить»:

**Повторная проверка → Доказательства → Резервная копия → Отключение автозапуска → Остановка → Карантин → Проверка → Откат**

Ручной инструмент Expert не заменяет текущую логику Easy-сценария подозрительной фоновой активности.

### Единый механизм восстановления

Рабочая схема для унификации безопасных изменений системы:

**Обнаружение → Проверка условий → Резервная копия → Исправление → Проверка результата → Откат**

В этот механизм планируется постепенно свести существующие действия с DNS, прокси, службами, устройствами и безопасностью.

## 1.2.0 — Восстановление и продолжение после перезагрузки

- файл состояния незавершённой операции;
- контроль целостности состояния;
- одноразовое задание в Планировщике заданий;
- продолжение проверки после входа в Windows;
- удаление одноразового задания после завершения;
- расширение раздела восстановления;
- безопасный режим только как пошаговый сценарий, без автоматического изменения BCD.

## 1.3.0 — Правила диагностики и база событий

Текущий вариант задачи — отделить правила диагностики от интерфейса и конкретных PowerShell-команд.

Пример структуры правила:

```text
Rule ID
Category
Conditions
Severity
Evidence
Explanation
WhyImportant
NextStep
RepairAction
Confidence
```

Отдельная задача — база интерпретации журнала событий Windows: значение события, контекст, типичные причины, взаимосвязи и полезность для текущего симптома.

## 1.4.0 — Оборудование и драйверы

### Датчики оборудования

Кандидаты для реализации:

- температуры CPU/GPU/накопителей;
- частоты;
- нагрузки;
- питание;
- вентиляторы;
- признаки снижения частот из-за перегрева или ограничений питания.

### Управление хранилищем драйверов

Кандидаты для раздела Expert:

- связь драйвера с устройством;
- производитель, версия и дата;
- старые пакеты;
- наличие цифровой подписи;
- резервное копирование и экспорт;
- безопасные сервисные действия.

## 1.5.0 — Безопасность 2.0

Рабочий список:

## 1.6.0 — Наблюдение за системой и отчёты

### Expert → Наблюдение за системой

Черновая идея: пользователь запускает запись, воспроизводит проблему и останавливает наблюдение. **Owl-IN ServiceKit** собирает временную цепочку:

**процесс → дочерний процесс → файл/модуль → реестр → служба/задание → сеть**

### Отчёты и пакет диагностики

- межсессионная история;
- сравнение запусков;
- TXT / JSON / HTML;
- диагностический ZIP;
- очистка чувствительных данных перед экспортом.
