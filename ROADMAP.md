## 1.1.0 — Диспетчер процессов и единый механизм восстановления

### Expert → Процессы

Текущий план задач:

- живой список процессов;
- PID / PPID;
- CPU / GPU / RAM;
- путь к EXE;
- цифровая подпись и издатель;
- SHA-256;
- дерево процессов;
- сетевые соединения;
- поиск процесса, удерживающего файл;
- завершение процесса;
- завершение дерева;
- защита критических системных процессов;
- переход к связанным Run/RunOnce, службам и заданиям планировщика;
- действие **«Обезвредить»** для подозрительного процесса.

Черновая схема действия «Обезвредить»:

**Повторная проверка → Доказательства → Резервная копия → Отключение автозапуска → Остановка → Карантин → Проверка → Откат**

Ручной инструмент Expert не заменяет текущую логику Easy-сценария подозрительной фоновой активности.

### Единый механизм восстановления

Рабочая схема для унификации безопасных изменений системы:

**Обнаружение → Проверка условий → Резервная копия → Исправление → Проверка результата → Откат**

В этот механизм планируется постепенно свести существующие действия с DNS, прокси, службами, устройствами и безопасностью.

## 1.2.0 — Действующий Easy Mode и продолжение после перезагрузки

### Реальные действия во всех сценариях Easy Mode

Главная цель версии: Easy Mode должен не только находить и объяснять проблему, но и доводить пользователя до фактического результата. Каждый сценарий обязан завершаться понятным действием внутри Easy Mode, повторной проверкой и итогом **«Исправлено»**, **«Не помогло — изменение отменено»** либо **«Автоматически исправить небезопасно»** с конкретным следующим шагом.

План действий по сценариям:

- интернет не работает — восстановление подтверждённой неисправности DNS, proxy, служб подключения или сетевого адаптера;
- сайты не открываются / ошибка DNS — очистка DNS-кеша, возврат DNS к DHCP и сброс подтверждённого proxy;
- после VPN пропал интернет — устранение оставшегося WinINET/WinHTTP proxy, DNS-настроек и других подтверждённых последствий VPN;
- Wi-Fi не работает — запуск или перезапуск WLAN AutoConfig, переподключение адаптера и повторная проверка;
- Windows Update не работает — восстановление состояния необходимых служб и повторная проверка Windows Update без автоматической установки обновлений;
- Windows тормозит или зависает — действие по подтверждённой причине нагрузки, без универсальной «оптимизации»;
- нет звука — восстановление аудиослужб и повторная проверка устройств вывода;
- Bluetooth не работает — восстановление службы Bluetooth и повторное обнаружение устройств;
- принтер не печатает — восстановление Print Spooler с сохранением очереди и повторная проверка;
- проблема с устройством или драйвером — безопасное повторное сканирование устройств и запуск подходящего системного средства; без автоматической переустановки драйверов;
- мало места или проблема с диском — расчёт безопасно освобождаемого места, подтверждаемая очистка выбранных временных данных и повторный замер;
- синий экран / перезагрузка / память — запуск подходящей диагностики и подготовка продолжения после перезагрузки; без автоматического изменения BCD, CHKDSK `/F` и параметров памяти;
- подозрительная фоновая нагрузка — отдельный Easy-алгоритм проверки и безопасного обезвреживания подтверждённого объекта; Expert Process Manager остаётся независимым инструментом.

Общие требования для каждого изменяющего действия:

**Обнаружение → Объяснение → Проверка условий → Резервная копия → Исправление → Проверка результата → Откат**

- действие предлагается только при подтверждённой причине;
- одно основное пользовательское действие вместо набора технических команд;
- после действия повторяется именно та проверка, которая первоначально выявила проблему;
- статус **«Исправлено»** выставляется только после успешной проверки результата;
- при неудачной проверке выполняется автоматический откат, если изменение обратимо;
- результат и этапы операции сохраняются в журнале Repair Engine;
- сценарий не должен заканчиваться только диагностикой или предложением перейти в Expert Mode;
- опасные или необратимые операции остаются пошаговыми и требуют явного решения пользователя.

### Восстановление и продолжение после перезагрузки

- файл состояния незавершённой операции;
- контроль целостности состояния;
- одноразовое задание в Планировщике заданий;
- продолжение проверки после входа в Windows;
- удаление одноразового задания после завершения;
- расширение раздела восстановления;
- безопасный режим только как пошаговый сценарий, без автоматического изменения BCD.

## 1.2.1 — Надёжные резервные копии и гарантированный откат

Исправить обнаруженный дефект Repair Engine: резервная копия может не создаваться,
из-за чего последующий откат недоступен.

Обязательные требования:

- изменяющее действие не запускается, пока резервная копия фактически не создана;
- после записи проверяются существование файла, его размер и возможность прочитать содержимое;
- backup содержит идентификатор операции, тип действия, дату, исходные значения и контрольную сумму;
- запись выполняется атомарно через временный файл с последующим переименованием;
- путь хранения выбирается один раз и фиксируется в журнале операции;
- ошибки записи в основной каталог обрабатываются явно, с проверяемым резервным каталогом;
- кнопка отката показывается только для существующей и успешно проверенной копии;
- перед откатом повторно проверяются целостность, тип и совместимость backup;
- после отката выполняется проверка фактического восстановления исходного состояния;
- если backup создать или проверить нельзя, операция останавливается до изменения Windows;
- интерфейс показывает отдельные результаты: **«Резервная копия создана»**,
  **«Изменение применено»**, **«Результат проверен»** и **«Откат доступен»**;
- добавить тесты создания и отката для DNS, WinINET proxy, WinHTTP proxy,
  служб, карантина и будущих изменяющих действий Easy Mode;
- проверить сценарии без прав администратора, недоступного каталога, повреждённого
  JSON, прерванной записи и запуска переносной версии из защищённой папки.

## 1.6.0 — Наблюдение за системой и отчёты

### Expert → Наблюдение за системой

Черновая идея: пользователь запускает запись, воспроизводит проблему и останавливает наблюдение. **Owl-IN ServiceKit** собирает временную цепочку:

**процесс → дочерний процесс → файл/модуль → реестр → служба/задание → сеть**

### Отчёты и пакет диагностики

- межсессионная история;
- сравнение запусков;
- TXT / JSON / HTML;
- диагностический ZIP;
- очистка чувствительных данных перед экспортом.
